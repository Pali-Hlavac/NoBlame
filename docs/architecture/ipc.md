# IPC: commands, events and streams

The webview talks to Rust only through Tauri commands and events. Types and wrappers are
generated by tauri-specta into `src/shared/ipc/bindings.ts` ([ADR 0003](../adr/0003-tauri-specta-typed-ipc.md)).
Never edit that file; run `pnpm bindings` (debug app runs regenerate it too). CI fails when the
committed file is out of date.

## Calling commands

```ts
import { commands, unwrap, call } from "@/shared/ipc/client";

const info = await unwrap(commands.getGitInfo()); // fallible: throws IpcError
const app = await call(commands.getAppInfo()); // infallible: only framework errors
```

Both helpers turn every failure into an `IpcError { code, message, hint }`. `code` is a backend
`ErrorCode` or `IPC_FAILURE` for framework errors such as "command not allowed"
([ADR 0006](../adr/0006-error-model.md)).

## Access control

Every command is listed in `APP_COMMANDS` in `src-tauri/build.rs`, which generates an
`allow-<kebab-name>` permission. Each capability file grants permissions to window labels:

| Capability               | Windows  | Grants                                                                          |
| ------------------------ | -------- | ------------------------------------------------------------------------------- |
| `capabilities/main.json` | `main`   | Every app command, `dialog:allow-open`, `core:event:default`                    |
| `capabilities/task.json` | `task-*` | Read-only commands, settings and window context; no dialogs, no opening windows |

A command that returns "not allowed" is missing from `APP_COMMANDS` or from a capability.

| `get_git_info` | `git_env` | yes | `Result<GitInfo>` | Locates git again and reports path, version, support |

impl (`unknown`), because specta refuses `serde_json::Value`'s 64-bit numbers. The frontend
validates it (`features/workbench/lib/layout.ts`, version 1).

Repository errors: `NOT_A_REPOSITORY` (neither the folder nor a parent is a repository; hint:
choose another folder or create one), `UNTRUSTED_REPOSITORY` (owned by another user and not in
`safe.directory`; the hint shows the `git config --global --add safe.directory` command, which
NoBlame never runs itself), `GIT_FAILED` (gix could not read the repository), `NOT_FOUND`
(session already closed).

`get_git_info` errors: `GIT_NOT_FOUND` (with an install hint per OS), `GIT_UNUSABLE` (found but
cannot start, does not answer within 10 s, or prints something that is not a git version).

## Events

| Event                    | Payload                                    | Sent when                                                               | Listener reaction                                                                                                                      |
| ------------------------ | ------------------------------------------ | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `repositories-requested` | `null`                                     | A launch asked the main window to open a repository                     | Call `take_repository_requests` and open tabs                                                                                          |
| `repository-changed`     | `RepositoryChanged { id, refs, workTree }` | The watcher saw a change made outside the app (after a 300 ms debounce) | `workTree` or `refs`: refetch the status; `refs`: `refresh_repository`, then `reload_graph` and refetch everything read from the graph |

`repositories-requested` carries no data on purpose: the main window also drains the queue when
it starts, so a request that arrives before the window subscribed is not lost.
`repository-changed` may carry data, because a missed change is harmless: the status is also
read when the window regains focus.

## Types

The full, documented list is in `bindings.ts`. Important shapes:

- `AppError { code: ErrorCode; message: string; hint: string | null }`
- `GitInfo { path; version; supported; minimumVersion }`
- `WindowContext = { kind: "main" } | { kind: "task"; task: TaskKind; path: string }`
- `TaskKind = "log" | "commit" | "diff" | "blame" | "fileHistory" | ... | "init"`
- `RepoSummary { id; name; path; gitDir; kind; head; isShallow; hasCommitGraph }`, where `kind` is
  `normal | bare | linkedWorktree | submodule` and `head` is `{ kind: "branch" | "unborn", name }`
  or `{ kind: "detached", id }`
- `GraphSummary { rows; totalRows; filter; maxLanes; blockRows; headRow; missingParents; buildMs;
generation }`: `rows` are the shown commits, `totalRows` the commits without the filter
- `GraphFilterDto { tips; firstParent; noMerges; author; message; path }` with `tips` one of
  `{ type: "all" }`, `{ type: "head" }` or `{ type: "refs", refs: { kind, name }[] }`;
  `author` and `message` are `null` or plain text matched ignoring case; `path` is `null` or a
  pathspec relative to the repository root (absolute paths inside it are made relative). A
  newer call cancels a search under way, which then fails with `CANCELLED`
- `CommitLinkDto { id; row }` for parents and children in commit details: `row` is `null` when
  the filter hides that commit
- `CommitRowDto { row; id; summary; authorName; authorEmail; authorTime; parentCount; refs }`
  with `refs: RefLabel[]`, `RefLabel { name; kind: "head" | "branch" | "remote" | "tag"; isHead }`

Rust `f64` fields (`authorTime`, `buildMs`, `lastOpened`) are typed `number | null` in the
bindings, because serde_json writes NaN and infinity as `null`. The UI handles `null` (an
unknown date shows as empty).

Paths cross the boundary as strings. Paths that are not valid Unicode are rejected with an
`INVALID_INPUT` error for now instead of being changed silently. Git data (paths, messages) will
travel as bytes where round trips back to git are needed.

## Rules for new IPC

- Commands are verbs (`get_commit`, `stage_hunks`); every command doing I/O is `async`.
- No `i64`/`u64` in exported types (specta refuses them); use `f64` seconds for times and
  strings for exact large values.
- Never send thousands of items as JSON. Use binary results (below) or paging.
- Follow "Adding a Tauri command end to end" in [CLAUDE.md](../../CLAUDE.md).

## Binary graph blocks

Graph geometry never travels as JSON. `get_graph_block(id, block)` returns rows
`block * 256 .. block * 256 + 255` as raw bytes ([ADR 0008](../adr/0008-binary-graph-blocks.md)).
The Rust side returns a `RawBytes` value, which Tauri sends as a raw `InvokeResponseBody`, so
the webview receives an `ArrayBuffer` without JSON encoding. Its TypeScript type in the bindings
is `unknown`; `fetchGraphBlock` (`src/features/graph/api/graph.ts`) narrows it to `ArrayBuffer`
and reports anything else as an `IPC_FAILURE`.

Format (version 1, all numbers little-endian; source of truth:
`crates/git-core/src/graph/encode.rs`, decoder: `src/features/graph/lib/decode.ts`):

```text
header (12 bytes): version u8, reserved u8, reserved u16, first_row u32, row_count u32
per row (8 bytes): lane u16, color u16, flags u8, reserved u8, edge_count u16,
then per edge (6 bytes): from u16, to u16, color u16
```

- `lane` is the column of the commit's node; `color` is the lane colour id truncated to 16 bits
  (the UI cycles its palette with it).
- `flags`: `FLAG_MERGE = 1` (more than one parent), `FLAG_HEAD = 2` (HEAD points here).
- Each edge is a line from the centre of the previous row (lane `from`) to the centre of this
  row (lane `to`). To draw rows `a..=b`, draw the edges of rows `a..=b+1`.
- The decoder rejects other versions and truncated data with a `BlockFormatError`. Bump the
  version byte whenever the layout changes.

### Highlight overlay

`get_ancestry_block(id, row, block)` marks which nodes and lines of a block belong to the history
of the commit on `row` (version 1; source of truth: `encode_ancestry_block` in
`crates/git-core/src/graph/encode.rs`, decoder: `src/features/graph/lib/decodeAncestry.ts`):

```text
header (16 bytes): version u8, reserved u8, reserved u16, first_row u32, row_count u32,
                   edge_count u32
row_count bytes:   1 when the row's commit is in the history
edge_count bytes:  1 when the edge is lit, in the order of the same block's edges
```

A `row` outside the graph fails with `INVALID_INPUT` ("row N is outside the
graph").

`GraphSummary.generation` counts the graphs a session has shown: builds and filter changes. Row
numbers of different generations do not match, so text pages are keyed by it and the commit list
remounts (fresh block caches) when it changes.

Commit text is not part of the blocks: `get_commit_rows` returns it in pages of 100 rows, only for
what is on screen.
