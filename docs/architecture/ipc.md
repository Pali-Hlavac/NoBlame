# IPC: commands, events and streams

The webview talks to Rust only through Tauri commands and events. Types and wrappers are
generated by tauri-specta into `src/shared/ipc/bindings.ts` ([ADR 0003](../adr/0003-tauri-specta-typed-ipc.md)).
Never edit that file; run `pnpm bindings` (debug app runs regenerate it too). CI fails when the
committed file is out of date.

## Calling commands

```ts
import { commands, unwrap, call } from "@/shared/ipc/client";

const info = await unwrap(commands.getGitInfo()); // fallible: throws IpcError
const app = await call(commands.getAppInfo()); // infallible: only framework errors
```

Both helpers turn every failure into an `IpcError { code, message, hint }`. `code` is a backend
`ErrorCode` or `IPC_FAILURE` for framework errors such as "command not allowed"
([ADR 0006](../adr/0006-error-model.md)).

## Access control

Every command is listed in `APP_COMMANDS` in `src-tauri/build.rs`, which generates an
`allow-<kebab-name>` permission. Each capability file grants permissions to window labels:

| Capability               | Windows  | Grants                                                                          |
| ------------------------ | -------- | ------------------------------------------------------------------------------- |
| `capabilities/main.json` | `main`   | Every app command, `dialog:allow-open`, `core:event:default`                    |
| `capabilities/task.json` | `task-*` | Read-only commands, settings and window context; no dialogs, no opening windows |

A command that returns "not allowed" is missing from `APP_COMMANDS` or from a capability.

## Commands

| Command                    | Module     | Async | Returns                 | Purpose                                                    |
| -------------------------- | ---------- | ----- | ----------------------- | ---------------------------------------------------------- |
| `get_app_info`             | `app_info` | no    | `AppInfo`               | Name, version, OS and architecture                         |
| `get_settings`             | `settings` | yes   | `Result<Settings>`      | Saved preferences, or defaults                             |
| `update_settings`          | `settings` | yes   | `Result<Settings>`      | Replaces and saves preferences (atomic write)              |
| `get_git_info`             | `git_env`  | yes   | `Result<GitInfo>`       | Locates git again and reports path, version, support       |
| `get_window_context`       | `windows`  | no    | `Result<WindowContext>` | What the calling window is: `main` or `task` + task + path |
| `take_repository_requests` | `windows`  | no    | `string[]`              | Drains repositories requested from the command line        |
| `open_task_window`         | `windows`  | yes   | `Result<null>`          | Opens a task window, like `noblame <task> <path>`          |

`get_git_info` errors: `GIT_NOT_FOUND` (with an install hint per OS), `GIT_UNUSABLE` (found but
cannot start, does not answer within 10 s, or prints something that is not a git version).

## Events

| Event                    | Payload | Sent when                                           | Listener reaction                             |
| ------------------------ | ------- | --------------------------------------------------- | --------------------------------------------- |
| `repositories-requested` | `null`  | A launch asked the main window to open a repository | Call `take_repository_requests` and open tabs |

Events carry no data on purpose: the main window also drains the queue when it starts, so a
request that arrives before the window subscribed is not lost.

## Types

The full, documented list is in `bindings.ts`. Important shapes:

- `AppError { code: ErrorCode; message: string; hint: string | null }`
- `GitInfo { path; version; supported; minimumVersion }`
- `WindowContext = { kind: "main" } | { kind: "task"; task: TaskKind; path: string }`
- `TaskKind = "log" | "commit" | "diff" | "blame" | "fileHistory" | ... | "init"`

Paths cross the boundary as strings. Paths that are not valid Unicode are rejected with an
`INVALID_INPUT` error for now instead of being changed silently. Git data (paths, messages) will
travel as bytes where round trips back to git are needed.

## Rules for new IPC

- Commands are verbs (`get_commit`, `stage_hunks`); every command doing I/O is `async`.
- No `i64`/`u64` in exported types (specta refuses them); use `f64` seconds for times and
  strings for exact large values.
- Never send thousands of items as JSON. Use the binary channel below or paging.
- Follow "Adding a Tauri command end to end" in [CLAUDE.md](../../CLAUDE.md).

## Binary graph stream (planned, M2)

The commit graph is streamed as binary batches over a Tauri `Channel` so that a million rows
never become JSON. The format (row layout, lane encoding, batch header, versioning) is designed
and documented here in M2 together with [ADR 0008](../adr/README.md). Nothing is implemented
yet.
